# W12 — GitHub Actions CI 파이프라인 구축

> **상태**: ✅ 완료
> **완료일**: 2026-05-31

---

## 목표

PR 및 main 브랜치 push 시 자동으로 빌드 검증, 컨테이너화 검증, Spring 유닛 테스트, API 통합 테스트를 수행하는 CI 파이프라인 구축.

---

## 배경

W11까지 코드가 완성되었으나 GitHub에 CI가 전혀 없었다. main에 직접 push해도 빌드 오류나 테스트 실패를 자동으로 감지하는 수단이 없었다. 또한 Spring 테스트는 `contextLoads` 하나뿐이고 Makefile의 `bootJar`는 `-x test`로 테스트를 제외하는 상태였다.

---

## 구축 내용

### CI Job 구조

```
build-frontend ─────────────────────────────┐
build-spring (bootJar -x test) ─────────────┤──► integration-test
build-fastapi (docker build) ───────────────┘
test-spring (gradle test + H2) ─────────────────────────────────►│
```

- `integration-test`는 위 4개 Job이 모두 성공해야 실행
- **트리거**: `push: [main]`, `pull_request: [main]`

## Job별 상세

### Job 1 — `build-frontend`
- Node 20, `npm ci && npm run build`
- `dist/` 아티팩트 업로드 → `integration-test`에서 사용 (Nginx가 마운트)

### Job 2 — `build-spring`
- Java 21 Temurin, `./gradlew bootJar -x test --no-daemon`
- JAR 빌드 성공 여부만 검증 (테스트는 별도 Job)

### Job 3 — `test-spring`
- `./gradlew test --no-daemon` (H2 인메모리 DB)
- 실패 시에도 `spring-test-report` 아티팩트 업로드 (`if: always()`)

### Job 4 — `build-fastapi`
- `docker build -t inseoul-fastapi ./backend`
- 이미지 push 없이 빌드 성공 여부만 검증

### Job 5 — `integration-test`
- `frontend-dist` 아티팩트 다운로드 → `./dist/` 배치
- `.env` 파일 인라인 생성 (더미 값, GitHub Secrets 불필요)
- `docker compose -f docker-compose.yml -f docker-compose.ci.yml up -d --build`
- Spring 헬스체크 폴링 (최대 90초, 5초 간격)
- FastAPI 헬스체크 폴링 (최대 30초)
- `bash scripts/ci-smoke-test.sh` 실행 (12개 시나리오)
- `docker compose down -v` (`if: always()`)

## CI 환경변수 처리 방식

| 변수 | CI 값 | 비고 |
|------|-------|------|
| `JWT_SECRET` | 더미 32자+ 문자열 | JJWT 최소 길이 충족 |
| `DB_PASSWORD` | `ci-test-password` | 컨테이너 간 통신용 |
| `KAKAO_CLIENT_ID/SECRET` | `dummy-*` | Spring 컨텍스트 로딩 통과용 |
| `GOOGLE_CLIENT_ID/SECRET` | `dummy-*` | 동일 |
| `MOLIT_API_KEY` | (빈값) | `MolitClient` graceful skip 처리 |
| `OPENAI_API_KEY` | (빈값) | FastAPI `/health`는 정상 동작, 챗 테스트 제외 |

**GitHub Secrets 불필요** — 모든 값이 더미이거나 빈값으로 처리 가능.

## 주요 설계 결정

### Flyway 비활성화 (유닛 테스트)
`V1__init.sql`에 `TINYINT UNSIGNED`, `ON UPDATE CURRENT_TIMESTAMP` 등 MySQL 전용 구문이 포함되어 H2 호환 문제가 예상됨. 유닛 테스트는 DB 스키마가 불필요하므로 `spring.flyway.enabled: false`로 처리. 실제 MySQL 마이그레이션 검증은 `integration-test` Job의 docker compose에서 수행.

### H2 인메모리 DB (테스트 프로파일)
기존 `application-prod.yml`은 MySQL만 사용. 테스트용 `application-test.yml`에 H2 datasource 추가 및 `@ActiveProfiles("test")`로 활성화.

### 챗봇 테스트 제외
기존 `regression_test.sh`의 시나리오 25 (Chat SSE)는 실제 `OPENAI_API_KEY`가 필요하고 30초 타임아웃이 발생함. CI 스모크 테스트에서 제외하고 FastAPI `/health` 엔드포인트만 검증.

### Branch Protection 권장 사항
현재 main 직접 push 시 CI가 사후 실행됨 (실패해도 코드가 main에 반영됨). GitHub → Settings → Branches → Require status checks to pass 설정으로 CI 통과 전 머지 차단 가능.
