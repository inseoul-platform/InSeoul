# W2 — 인증 (JWT + OAuth2)

> **상태**: ✅ 완료 (OAuth2 실 키 검증 보류)  
> **기간**: W1 완료 후

---

## 목표

JWT 자체 회원가입/로그인과 Kakao/Google OAuth2를 동시에 지원. Refresh Token 회전 정책으로 보안 강화.

---

## 기술 결정

| 항목 | 결정 | 이유 |
|------|------|------|
| JWT 알고리즘 | HS256 (jjwt 0.12.6) | 단순성, 서버 단독 검증 |
| Access Token 유효기간 | 15분 | 탈취 피해 최소화 |
| Refresh Token 유효기간 | 7일 + 회전 정책 | 매 갱신마다 새 토큰 발급, 이전 토큰 revoke |
| Refresh Token 저장 | SHA-256 해시만 DB 저장 | 원본 노출 방지 |
| jti (JWT ID) | UUID 추가 | 같은 초에 발급된 토큰의 해시 충돌 방지 |
| 패스워드 해싱 | BCrypt strength=12 | 단방향 해시, 레인보우 테이블 방어 |
| PasswordEncoder 위치 | 별도 `PasswordEncoderConfig` 클래스 | SecurityConfig 순환 의존성 방지 |
| CORS | `CorsConfigurationSource` Bean | Spring Security 6 요구사항 (CorsFilter 불가) |
| 401 응답 | `AuthenticationEntryPoint` JSON 반환 | 빈 바디 대신 `ApiResponse.fail()` 반환 |
| OAuth2 콜백 | URL fragment `#accessToken=...&refreshToken=...` | JS가 sessionStorage 이관 후 `history.replaceState` |

## 산출물

| 파일 | 설명 |
|------|------|
| `config/SecurityConfig.java` | SecurityFilterChain, STATELESS, 공개/보호 경로 분리 |
| `config/PasswordEncoderConfig.java` | BCrypt Bean (순환 의존성 분리) |
| `config/CorsConfig.java` | CorsConfigurationSource Bean |
| `auth/security/JwtTokenProvider.java` | access/refresh 토큰 발급·검증, SHA-256 유틸 |
| `auth/security/JwtAuthenticationFilter.java` | Bearer 토큰 파싱 → SecurityContext 설정 |
| `auth/controller/AuthController.java` | signup, login, refresh, logout, me |
| `auth/service/AuthService.java` | 비즈니스 로직, BCrypt 해싱, 토큰 발급 |
| `auth/oauth2/OAuthAttributes.java` | Kakao/Google 사용자 속성 매핑 |
| `auth/oauth2/CustomOAuth2UserService.java` | OAuth2 사용자 DB upsert |
| `auth/oauth2/OAuth2SuccessHandler.java` | JWT 발급 후 프론트 redirect |
| `auth/mapper/UserMapper.java` + XML | users, oauth_accounts insert/find |
| `auth/mapper/RefreshTokenMapper.java` + XML | refresh_tokens CRUD + revoke |

## API

| Method | Path | 인증 | 설명 |
|--------|------|:----:|------|
| POST | /api/auth/signup | — | 이메일+패스워드 회원가입 |
| POST | /api/auth/login | — | 로그인 → access/refresh 토큰 |
| POST | /api/auth/refresh | — | Refresh 토큰 갱신 (회전) |
| POST | /api/auth/logout | JWT | Refresh 토큰 전체 revoke |
| GET | /oauth2/authorization/{provider} | — | OAuth2 로그인 시작 (provider: kakao/google) |
| GET | /api/auth/me | JWT | 현재 로그인 사용자 정보 |

### 응답 예시

```json
// POST /api/auth/login
{
  "success": true,
  "data": {
    "accessToken": "eyJhbGci...",
    "refreshToken": "eyJhbGci...",
    "user": { "id": 1, "email": "user@example.com", "nickname": "홍길동", "provider": "local" }
  }
}
```

## 인증 흐름

```
[자체 로그인]
POST /api/auth/signup → BCrypt 해싱 → users 저장 → 기본 profile/simConfig 생성 → 토큰 발급
POST /api/auth/login  → BCrypt 검증 → 토큰 발급 → refresh 해시 DB 저장

[토큰 갱신]
POST /api/auth/refresh
  → SHA-256(refreshToken) 조회 → revoked/expires 확인
  → 기존 토큰 revoke → 새 토큰 쌍 발급

[OAuth2 (Kakao/Google)]
브라우저 GET /oauth2/authorization/{provider}
  → provider 동의 화면
  → Spring 콜백 /login/oauth2/code/{provider}
  → CustomOAuth2UserService: provider+id로 조회 → 없으면 생성
  → OAuth2SuccessHandler: 자체 JWT 발급
  → 프론트 redirect: /#accessToken=...&refreshToken=...
```

## DoD 체크리스트

- [x] signup → login → Bearer → `/api/auth/me` 성공
- [x] refresh → 새 access/refresh 토큰 발급 (jti UUID로 해시 충돌 방지)
- [x] logout → refresh 토큰 revoked=1, 재사용 시 TOKEN_INVALID
- [x] 인증 없이 보호 경로 → 401 JSON 응답 (빈 바디 아님)
- [x] 잘못된 입력 → 400 INVALID_INPUT
- [x] 중복 이메일 → 409 DUPLICATE_EMAIL
- [ ] Kakao/Google OAuth2 브라우저 플로우 (실 키 등록 후 확인)

## 주요 트러블슈팅

| 문제 | 원인 | 해결 |
|------|------|------|
| 순환 의존성 | SecurityConfig → OAuth2SuccessHandler → AuthService → PasswordEncoder (SecurityConfig 내 Bean) | PasswordEncoder를 `PasswordEncoderConfig`로 분리 |
| Refresh Token 해시 충돌 | 같은 초에 발급 → iat 동일 → SHA-256 동일 → `uq_token_hash` 위반 | `generateRefreshToken()`에 `.id(UUID.randomUUID())` jti 추가 |
| 401 빈 바디 | Spring Security 기본 동작이 빈 응답 반환 | `jsonAuthEntryPoint()` Bean으로 JSON `ApiResponse.fail()` 직접 write |
| CORS 설정 충돌 | `CorsFilter` Bean + Security 내 `.cors()` 중복 | `CorsFilter` 제거, `CorsConfigurationSource` Bean만 사용 |
